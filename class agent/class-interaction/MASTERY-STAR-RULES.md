# 掌握星级规则

本文件定义知识点掌握度的 0-5 星标准。知识点来自 `KNOWLEDGE-BASE.md`，标注记录来自 `class-point/points`，当前掌握状态写入 `student-workspace/data/mastery-state.json`，每次变化追加到 `mastery-history.json`。

## 核心边界

1. 标注和掌握度不是同一件事。标注是学习过程中的原始记录，掌握度是基于证据得到的结果。
2. 没有检测或接触过的知识点为 0 星，前端不绘制星星，只显示“未检测”。
3. 知识点一旦产生有效标注，最低为 1 星；标注本身不能生成 5 星。
4. 只有通过正式考核，并且满足 `KNOWLEDGE-BASE.md` 中的掌握表现，才能标为 5 星。
5. 学生自报“掌握”只是一条标注，不等于 5 星，也不直接覆盖已有星级。

## 星级定义

| 星级 | 状态 | 进入条件 | 前端表现 |
| --- | --- | --- | --- |
| 0 | 未检测 | 知识点存在，但没有标注、答题或考核记录 | 不显示星星，显示“未检测” |
| 1 | 已标注 | 产生了与该知识点关联的有效标注 | 显示 1 星 |
| 2 | 初步理解 | 能识别概念或复述要点，但仍需明显提示 | 显示 2 星 |
| 3 | 理解中 | 能用自己的话解释，并完成带提示的基础任务 | 显示 3 星 |
| 4 | 接近掌握 | 能独立解释并完成基础任务，但还没有通过正式考核 | 显示 4 星 |
| 5 | 已掌握 | 通过正式考核，证据满足知识点掌握表现 | 显示 5 星 |

## 标注如何影响星级

旧标签继续保留，不新增另一套标签：

- `掌握 / 没掌握` 仍表示学生的主观标记。
- `完全不懂 / 没有听到 / 部分理解 / 自定义标签` 仍是标注原因。
- 首次有效标注把对应知识点从 0 星提升为 1 星。
- 标注只有关联到稳定 `KP-xxx` 后，才允许影响掌握状态。
- 同一知识点的多条标注可以并存，但 1 星不会因为多次标注重复加分。

## 答疑与考核如何影响星级

- 答疑中出现初步理解证据：可调整为 2 星。
- 能在提示下解释或完成基础任务：可调整为 3 星。
- 能独立解释并完成基础任务：可调整为 4 星。
- 5 星必须来自明确考核，不得直接由“已解决”的标注状态生成。
- 没有产生新证据时，保留原星级，只更新标注状态和最近证据。

## 当前状态字段

`mastery-state.json` 中每个知识点使用以下字段：

```json
{
  "kp_id": "KP-002",
  "stars": 1,
  "status": "已标注",
  "assessment_status": "未考核",
  "annotation_ids": ["point-001"],
  "last_annotation_id": "point-001",
  "last_source": "class_point",
  "last_evidence": "标记点 point-001，尚无正式考核证据。",
  "updated_at": "2026-09-07T10:00:00+08:00"
}
```

`assessment_status` 只允许：

- `未考核`
- `考核中`
- `已通过`

## 历史记录字段

每次星级或状态变化都追加一条历史，不覆盖旧记录：

```json
{
  "history_id": "mh-001",
  "student_id": "student-001",
  "kp_id": "KP-002",
  "old_stars": 0,
  "new_stars": 1,
  "old_status": "未检测",
  "new_status": "已标注",
  "source": "class_point",
  "evidence": "新增标记点 point-001。",
  "annotation_id": "point-001",
  "occurred_at": "2026-09-07T10:00:00+08:00"
}
```

`source` 只允许：

- `class_point`
- `dialogue`
- `assessment`
- `manual`
