# GLOSSARY Format

`GLOSSARY.md` stores the precise vocabulary this workspace has earned. It is a compressed record of concepts the student now understands, not a dictionary to learn from scratch. The agent can reach for these terms when wording matters, but the student's clear everyday language is always acceptable in dialogue.

## Template

```md
# {Topic} Glossary

{One or two sentence description of the language this glossary governs.}

## Terms

**{Canonical term}**:
{One or two sentences defining what the term IS.}
_Avoid_: {alias or fuzzy wording}

**{Another canonical term}**:
{Definition.}
_Avoid_: {alias or fuzzy wording}
```

## Rules

- Add a term only when the student has evidenced understanding of it. Being introduced to a concept is not enough; wait until the student can use it correctly.
- Pick one opinionated term per concept and list competing words as aliases to avoid.
- Keep definitions tight. Define what the term IS.
- Use glossary terms inside definitions once they exist.
- Group terms under subheadings when natural clusters emerge.
- Flag workspace-specific meanings explicitly.
- Revise definitions in place as the student's understanding deepens. Leave no stale entry behind.
